# runtime-logs Specification

## Purpose

让管理员在客户端读取后端统一应用日志入口产生的最近运行记录，通过筛选和刷新定位同步及服务错误，同时限定保留容量、排除敏感凭据，并明确重启后的历史可用范围。

## Requirements

### Requirement: 日志保留范围有界且属于当前进程

后端 SHALL 在保留现有控制台输出的同时，保留当前进程统一应用日志入口产生的最近记录，容量最多 500 条、每条展示消息最多 4096 字符，截断时明确标记。每条记录 MUST 包含标识、时间、级别、模块和消息。缓冲区满时 MUST 淘汰写入最早的记录，重启后 MUST 清空历史。

#### Scenario: 连续日志超过容量
- **WHEN** 当前进程产生超过 500 条应用日志
- **THEN** 仅保留最新 500 条，日志读取仍可正常工作，超长消息有可识别的截断标记

#### Scenario: 后端重启
- **WHEN** 管理员在后端重启后读取日志
- **THEN** 只能看到新进程已产生的记录，界面明确说明日志仅属于当前进程且重启后清空

### Requirement: 管理员可以筛选最近日志

受保护的 `GET /admin/logs` SHALL 支持按单个日志级别、模块和消息关键词组合筛选，关键词忽略大小写。筛选 MUST 在保留记录范围内执行，返回最新匹配记录并按时间从新到旧展示。同一时间戳的记录按写入顺序倒序展示。默认最多返回 100 条，单次上限 200 条。非法级别或非法条数 MUST 返回 HTTP 400。

#### Scenario: 组合筛选错误日志
- **WHEN** 管理员选择错误级别并指定模块和关键词
- **THEN** 返回的每条记录同时满足这些筛选条件，不超过请求条数上限，界面显示当前筛选条件

#### Scenario: 最新匹配日志优先
- **WHEN** 匹配记录超过请求条数，且其中有记录的时间戳相同
- **THEN** 接口按时间从新到旧选取并返回指定条数的记录，时间相同则后写入的优先，界面按返回顺序显示

#### Scenario: 没有匹配记录
- **WHEN** 当前进程的保留记录均不满足筛选条件
- **THEN** 接口返回空结果，客户端显示无匹配日志，而不是加载失败

### Requirement: 凭据不会进入客户端日志

后端 MUST 在日志进入内存缓存前完成安全格式化与脱敏，不缓存原始请求、响应、Cookie 或异常对象；密码、访问令牌、Authorization、会话凭据、API 密钥和私有 URL 中的凭据 MUST NOT 出现在返回消息中。控制台与客户端 SHALL 使用同一份已处理消息；客户端 MUST 将日志作为纯文本渲染。

#### Scenario: 异常携带敏感请求信息
- **WHEN** 网络异常包含 Authorization、Cookie、私有 Feed 查询参数或其他已识别的凭据
- **THEN** 缓存及接口返回中只出现已脱敏的诊断信息，不包含原始凭据

#### Scenario: 日志包含 HTML 或脚本片段
- **WHEN** 日志消息含有 HTML 标签或脚本样式文本
- **THEN** 客户端按普通文本显示该内容，不执行脚本或将其插入为 HTML

### Requirement: 日志自动刷新可控制

日志页签 SHALL 提供手动刷新、默认开启的每 5 秒自动刷新以及暂停自动刷新的操作。只有已登录管理员正在可见页面查看日志页签时才能轮询；面板关闭、切换页签、访客预览、页面隐藏或会话失效时 MUST 停止轮询。普通读取失败 SHALL 显示错误状态并允许重试，HTTP 401 MUST 触发受限数据清理。

#### Scenario: 暂停日志自动刷新
- **WHEN** 管理员暂停自动刷新
- **THEN** 客户端停止定期读取，保留当前筛选结果且仍可手动刷新

#### Scenario: 离开日志视图
- **WHEN** 管理员切换至同步页签、关闭面板或隐藏页面
- **THEN** 客户端停止日志轮询，重新查看时按现有筛选条件获取最新快照
