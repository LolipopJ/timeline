# Spec Delta

## Purpose

将 PSN、Xbox 与 Steam 的游戏完成里程碑可靠地同步到个人时间线，以接口证据和实际解锁时间表达本体与全成就完成情况，并通过独立、可恢复的同步状态减少重复请求，保持不同平台、账号与游戏记录互不干扰。

## ADDED Requirements

### Requirement: 三个平台可独立配置游戏完成同步

系统 SHALL 支持分别配置 PSN、Xbox 和 Steam 的游戏完成同步来源。每个来源 MUST 使用稳定的服务标识与目标账号标识，并遵守既有启停、同步计划和管理员手动同步规则。

#### Scenario: 同步同名的跨平台游戏

- **WHEN** 同一用户在 PSN 和 Steam 完成名称相同的游戏
- **THEN** 两个平台生成独立的完成记录，互不覆盖

#### Scenario: 平台游戏标识或账号不同

- **WHEN** 平台以不同游戏、奖杯集合或账号标识返回同名作品的完成记录
- **THEN** 系统按这些稳定标识分别同步，不按显示名称合并

#### Scenario: PSN 或 Xbox 任务省略目标账号

- **WHEN** PSN 任务省略 `accountId` 或 Xbox 任务省略 `xuid`
- **THEN** 系统使用该任务凭据所属账号的数字 ID 查询，并以该 ID 标识检查点和里程碑

#### Scenario: Steam 任务配置目标账号

- **WHEN** 配置 Steam 成就任务
- **THEN** 配置必须同时提供目标账号的 SteamID64 与该任务的 Web API Key

#### Scenario: Steam 游戏不在拥有目录中

- **WHEN** Steam 任务在 `gameOverrides` 中配置额外 AppID
- **THEN** 系统将这些 AppID 与 `GetOwnedGames` 的结果合并去重，并使用相同的成就定义与解锁时间校验

### Requirement: 授权材料仅保留在服务端

每个成就同步任务 SHALL 配置自己的凭据，包括 PSN 首次授权材料、Xbox 自有 OAuth 应用及持久化会话，或 Steam Web API Key。Xbox 会话 MUST 与配置的 OAuth 应用匹配。令牌刷新结果 MUST 持久保存；实际凭据 MUST NOT 出现在客户端响应、公开构建、日志、进程命令行或提交记录中。授权失败 MUST 提供不含凭据的来源上下文。

#### Scenario: 两个 PSN 任务使用不同的凭据

- **WHEN** 两个任务使用不同的 `psnNpsso` 并发同步
- **THEN** 每个任务只使用其凭据对应的授权会话

#### Scenario: 使用刷新后的会话重启

- **WHEN** 来源刷新令牌并持久化后重启服务端
- **THEN** 后续同步使用保存的有效会话，不要求每次人工重新登录

#### Scenario: 一个来源的授权失效

- **WHEN** 某来源的会话无法刷新
- **THEN** 该来源报告需要重新授权，保留已有记录与成功检查点，其他来源仍可执行

#### Scenario: Xbox 应用与会话不匹配

- **WHEN** 配置的 OAuth 应用无法刷新所提供的 Xbox 会话
- **THEN** 来源明确报告需要使用匹配应用重新授权，不自动切换其他应用或尝试兼容另一种会话格式

### Requirement: Python 运行依赖按 Xbox 来源隔离

启用 Xbox 成就来源的部署 SHALL 提供其所需的 Python 运行环境与依赖。环境缺失或不可用 MUST 使该来源明确失败，而不是作为没有新成就的成功结果。未启用 Xbox 时 MUST NOT 要求安装 Python，也 MUST NOT 影响其他已启用来源的同步。

#### Scenario: Xbox 缺少运行环境

- **WHEN** 已启用 Xbox 成就来源但其 Python 环境或依赖不可用
- **THEN** 本轮 Xbox 来源返回可定位的环境错误，保留成功检查点，其他来源仍可执行

#### Scenario: 仅使用其他平台

- **WHEN** 部署未启用 Xbox 成就来源
- **THEN** PSN、Steam 及其他既有来源不依赖 Python 环境即可正常运行

### Requirement: 本体里程碑必须具有接口证据

系统 SHALL 仅在有真实白金事件、明确的本体成就集合或经过核验的 Steam 本体 API ID 清单，且能确定完成时间时生成本体里程碑。系统 MUST 使用平台实际名称；无法证明本体范围的游戏 MUST 只参与全成就判定，不根据分数、成就名称或首次同步快照推测本体范围。

#### Scenario: PSN 返回已解锁的真实白金奖杯

- **WHEN** 接口返回已解锁的白金奖杯及有效解锁时间
- **THEN** 系统生成白金奖杯里程碑

#### Scenario: Xbox 或 Steam 返回可验证的本体集合

- **WHEN** 接口明确区分本体集合，集合全部完成且实际完成时间可确定
- **THEN** 系统生成对应的 Mythic 或本体全成就里程碑

#### Scenario: Steam 仅返回未区分本体与追加内容的默认集合

- **WHEN** Steam 没有明确区分本体集合，但该 AppID 配置了经核验的 `baseAchievementIds`
- **THEN** 系统逐项核验 API ID 存在且唯一，再按这些成就的实际解锁时间判定本体完成，全成就仍核验完整定义

#### Scenario: 游戏没有可验证的本体范围

- **WHEN** 接口只有完整成就列表，没有可验证的本体集合或真实白金事件
- **THEN** 系统不生成本体里程碑，仍可按完整成就列表生成全成就项

### Requirement: 全成就必须基于完整且非空的有效集合

系统 SHALL 在当前完整、非空的已发布有效永久成就集合全部解锁时判定全成就，包含接口可查询的追加内容。临时挑战与明确已归档的成就 MUST NOT 计入；只获得部分分页、不可见的集合或零项成就 MUST NOT 被判定为全成就。

#### Scenario: 本体完成但追加内容尚未完成

- **WHEN** 当前集合包含未解锁的追加成就
- **THEN** 系统保留已获得的本体里程碑，不生成本轮全成就记录

#### Scenario: 无成就或详情分页未完成

- **WHEN** 游戏没有成就，或成就详情请求没有取得完整结果
- **THEN** 系统不据此生成全成就里程碑

#### Scenario: 平台徽章未要求全部追加内容

- **WHEN** 平台返回完成徽章，但完整成就定义中仍有有效的未解锁追加成就
- **THEN** 系统不以该徽章单独认定全成就

### Requirement: 时间线日期使用实际解锁时间

白金项的创建时间 SHALL 为真实白金解锁时间；本体全成就与全成就项的创建时间 SHALL 为对应集合最后一个成就的实际解锁时间。缺失、无效或占位的时间 MUST NOT 用同步时间补齐，也 MUST NOT 生成伪造日期的里程碑。

#### Scenario: 首次同步历史成就

- **WHEN** 首次同步发现一个早已达成的全成就游戏且全部时间可确定
- **THEN** 时间线项使用最后一个成就的历史解锁时间

#### Scenario: 无法获得实际时间

- **WHEN** 完成状态可见但所需的实际解锁时间缺失或无效
- **THEN** 系统不生成该里程碑，并记录可定位且不含凭据的数据限制

### Requirement: 每个平台账号游戏最多保留两类里程碑

系统 SHALL 为每个服务下的平台、账号和游戏使用稳定的本体与全成就身份，最多保存两类时间线项。重复同步 MUST 更新同一逻辑条目，不以游戏名、解锁日期或成就总数作为会随更新改变的条目标识。

#### Scenario: 重复同步同一个完成事件

- **WHEN** 同一来源多次返回同一游戏的相同完成状态
- **THEN** 时间线项的身份保持不变，不产生重复条目

### Requirement: 同次完成合并且后续补完更新全成就项

系统 SHALL 在本体里程碑恰好完成整个成就集合时合并展示为本体里程碑，PSN 显示白金奖杯。后续新增成就并再次补完时，系统 SHALL 保留本体项，更新同一全成就项及其创建时间，MUST NOT 为每次追加内容新增条目。

#### Scenario: 白金是全成就的最后一项

- **WHEN** 获得白金同时完成游戏全部有效成就
- **THEN** 对外只展示并统计一条白金奖杯记录

#### Scenario: 同秒时间不足以证明同次完成

- **WHEN** 接口的时间精度使不同完成事件显示相同时间，但无法证明它们是同一次完成
- **THEN** 系统不单凭时间相等合并两条记录

#### Scenario: 多次追加内容后重新全成就

- **WHEN** 游戏已经记录本体与全成就，后续又新增成就并全部解锁
- **THEN** 本体项及其创建时间不变，同一全成就项更新到最新一次完成时间，最多仍为两类条目

#### Scenario: 曾合并的游戏补完新增成就

- **WHEN** 原本合并展示的游戏新增成就并于稍后补完
- **THEN** 展示原本体项和更新后的全成就项，两者具有各自的实际完成时间

### Requirement: 已达成的历史不会因新增未完成内容消失

系统 SHALL 保留已记录的历史完成里程碑，直到有新的、可验证的对应完成事件才更新该里程碑。新增未完成成就 MUST NOT 删除历史项或把旧项改写为当前未完成进度。首次同步 MUST NOT 猜测当前接口无法还原的历次完成历史。

#### Scenario: 更新后尚未恢复全成就

- **WHEN** 已记录全成就的游戏新增未完成成就
- **THEN** 既有全成就项保留原完成日期与达成时数据

### Requirement: 同步范围仅限制里程碑日期

奖杯来源 SHALL 遵守 `from`；早于该日期的里程碑 MUST NOT 新增。系统 MUST 仍取得判定完成所必需的旧成就。显式全量同步 SHALL 忽略成功检查点重新核验范围，但仍遵守 `from`、稳定身份及管理员软删除状态。

#### Scenario: 完成集合包含起始日期之前的成就

- **WHEN** 部分成就在 `from` 之前解锁，但最后一个成就在 `from` 之后解锁
- **THEN** 系统依据完整集合判定完成，并使用最后一次实际解锁时间创建条目

### Requirement: 每次执行独立记录时间与成功检查点

系统 SHALL 持久化每个奖杯来源的本次开始时间、结束时间和结果，并单独保留成功检查点。成功但没有新增奖杯的执行 MUST 推进检查点；失败 MUST NOT 推进成功检查点。重启后 MUST 能恢复检查点，不从时间线条目日期推算已执行范围。

#### Scenario: 长期没有新增奖杯

- **WHEN** 一轮同步成功且没有任何里程碑变化
- **THEN** 本轮执行时间与成功检查点仍被保存，下一轮无需重复首次全库详情拉取

#### Scenario: 详情请求失败后重试

- **WHEN** 来源在读取某游戏详情时失败
- **THEN** 系统记录失败时间并保留上次成功检查点，后续重试不会跳过未处理的数据

#### Scenario: 写入过程失败

- **WHEN** 里程碑与对应同步状态未能完整写入
- **THEN** 系统不发布一个声称已成功处理这些数据的新检查点

#### Scenario: Xbox 采集异常退出或结果不完整

- **WHEN** Xbox 采集超时、异常退出或返回无法验证的结果
- **THEN** 系统记录本轮来源失败并回收采集资源，不使用部分结果推进成功检查点，也不将其视为零事件成功

### Requirement: 常规同步避免全库成就详情重拉

系统 SHALL 在首次基线之后使用摘要变化发现和有界轮转复查选择详情请求对象，MUST NOT 在每次常规定时任务中拉取全部游戏的成就详情。接口限制所必需的轻量目录扫描 SHALL 被允许。轮转进度 MUST 持久化，在任务持续成功且数据可访问时最终复查全部已知候选游戏。

#### Scenario: Steam 无服务端增量游标

- **WHEN** 来源只能枚举游戏目录与逐游戏成就
- **THEN** 系统允许读取轻量目录，只对变化、新发现或本轮轮转选中的游戏请求详情

#### Scenario: 离线或延迟上报旧解锁

- **WHEN** 新可见的解锁时间早于成功检查点，或停机时间超过近期游戏列表覆盖范围
- **THEN** 系统仍能通过摘要变化或持续轮转复查发现该事件，不仅依据时间截断或近期列表过滤

#### Scenario: 平台限制请求频率

- **WHEN** 平台返回限流或暂时不可用
- **THEN** 系统采用有界重试或报告失败，不把未完成拉取当作成功，也不推进相关成功检查点

### Requirement: 系统合并与管理员操作互不覆盖

奖杯同步 SHALL 保留管理员设置的私密与软删除状态。系统合并与展开 MUST 使用独立于管理员软删除的状态；后续补完、刷新或全量核验 MUST NOT 自动恢复被管理员删除的条目，合并展示也 MUST NOT 绕过私密可见性。

#### Scenario: 管理员删除后再次补完

- **WHEN** 全成就项被管理员软删除，随后来源发现新的全成就时间
- **THEN** 系统更新其可验证数据但保留软删除状态，不重新公开该项

#### Scenario: 合并状态后来展开

- **WHEN** 追加成就使原先合并的两个里程碑需要分开展示
- **THEN** 系统仅改变合并状态，并继续遵守各条目的管理员私密及软删除状态
