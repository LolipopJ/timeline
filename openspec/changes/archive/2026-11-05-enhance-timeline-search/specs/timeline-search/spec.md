# Spec Delta

## Purpose

让时间线的筛选结果可以由 URL 完整表达并恢复，使读者能通过链接查看同一组结果、单条时间线项或某一来源类型的内容，并在分享与浏览历史之间保持一致。

## ADDED Requirements

### Requirement: URL 是时间线筛选状态的唯一来源

客户端 SHALL 从 URL 的 `search` 与 `orderBy` 参数初始化筛选状态，并在筛选状态变化后把相同的状态写回 URL。刷新页面、直接打开链接、浏览器后退与前进 MUST 恢复链接所描述的结果集与排序。未知参数 MUST NOT 影响结果，默认排序 MUST 在 URL 缺省 `orderBy` 时生效。

#### Scenario: 后退到上一个筛选结果

- **WHEN** 读者先搜索「旅行」再改为搜索「读书」，然后按下浏览器后退
- **THEN** 页面恢复到「旅行」的结果集，搜索框与 URL 同时显示该条件

#### Scenario: 直接打开带条件的链接

- **WHEN** 读者打开一个包含 `search` 与 `orderBy=updated_at` 的链接
- **THEN** 首屏按更新时间排序并只显示匹配该条件的内容，搜索框显示对应条件

### Requirement: 搜索框支持按时间线项 ID 筛选

搜索框 SHALL 支持 `id:<uuid>` 条件语法，条件在搜索框内以可删除的标签展示，且在 URL 的 `search` 参数中保持相同写法。删除标签 MUST 立即清除该条件并刷新结果。

#### Scenario: 输入合法的 ID 条件

- **WHEN** 读者输入 `id:6f1e6c1a-6a1f-4b0e-8f3f-2a1e3f6c9d10`
- **THEN** 搜索框显示该条件标签，列表只显示该条时间线项

#### Scenario: 删除 ID 标签

- **WHEN** 读者删除搜索框中的 ID 标签
- **THEN** 条件从搜索框与 URL 中移除，列表回到未按 ID 筛选的结果

### Requirement: 搜索框支持按来源类型筛选

搜索框 SHALL 支持 `type:<value>` 条件语法，`<value>` 对应服务配置中的服务 ID，条件以可删除的标签展示并保持写入 URL 的 `search` 参数。筛选结果 MUST 与该服务在时间线中实际产生的内容一致。删除标签 MUST 立即清除该条件并刷新结果。

#### Scenario: 输入类型条件

- **WHEN** 读者输入 `type:MyBlog`
- **THEN** 搜索框显示该条件标签，列表只显示该来源服务产生的时间线项

#### Scenario: 来源 ID 包含空格与撇号

- **WHEN** 读者选择服务 ID 为 `Lolipop's Thoughts` 的条目菜单中的「只看当前类型」，或打开 `search=type:Lolipop's Thoughts` 的链接
- **THEN** 列表显示该服务的全部可见条目，搜索框展示可删除的完整类型标签，不将 ID 的后半部分作为关键词；存在共同前缀时 SHALL 优先匹配最长的已知服务 ID

#### Scenario: 删除类型标签

- **WHEN** 读者删除搜索框中的 `type:MyBlog` 标签
- **THEN** 类型条件从搜索框与 URL 中移除，列表按剩余条件重新加载

### Requirement: 客户端可以获取已知服务 ID

服务端 SHALL 提供公开的 `GET /timeline-services`，仅返回配置服务及当前视角可见、未软删除条目来源的 ID 数组，不输出服务配置或凭据。接口 SHALL 复用列表的 `view` 校验与权限规则，管理员视角参数 MUST NOT 替代合法会话；客户端 MUST 按视角隔离清单缓存，并使用该清单判断 `type:` 条件是否已知。清单加载完成前 MUST NOT 将尚未识别的条件作为关键词请求时间线；清单加载失败时 SHALL 提供重试。

#### Scenario: 访客读取服务 ID

- **WHEN** 未登录访客请求 `/timeline-services`
- **THEN** 接口返回服务 ID 字符串数组，响应使用 `private, no-store`，不包含来源凭据与配置详情

#### Scenario: 来源配置已删除但条目仍然可见

- **WHEN** 一条公开时间线项的来源已从配置中移除
- **THEN** 访客的服务清单仍包含该来源 ID，直接链接与「只看当前类型」均能筛选该条目

#### Scenario: 私密与软删除来源不扩大可见性

- **WHEN** 未配置的历史来源仅存在私密条目或软删除条目
- **THEN** 访客清单不包含该来源，合法管理员可见私密条目来源，但仍不能通过软删除条目获得来源

### Requirement: 无法解析的条件文本按关键词搜索

缺少合法 UUID 的 `id:`、缺少已知服务 ID 的 `type:` 以及其它普通文本 MUST 作为关键词参与搜索，MUST NOT 产生按 ID 或按来源类型的筛选，也 MUST NOT 阻止普通搜索。

#### Scenario: 非法的 ID 文本

- **WHEN** 读者输入 `id:hello`
- **THEN** 该文本按普通关键词参与搜索，列表显示包含该文本的内容

### Requirement: ID 条件与其他条件互斥

`id:` 条件 SHALL 与关键词及 `type:` 条件互斥。写入 ID 条件时客户端 MUST 清空关键词与类型条件；写入关键词或类型条件时 MUST 清除 ID 条件。同一时刻 MUST 至多存在一个 ID 条件。

#### Scenario: 从 ID 结果回到关键词搜索

- **WHEN** 读者正查看某条时间线项的 ID 结果，然后在搜索框输入关键词
- **THEN** ID 条件被移除，列表按关键词重新加载

#### Scenario: 在关键词搜索中打开分享链接

- **WHEN** 读者已有关键词条件，然后打开一个只含 ID 条件的链接
- **THEN** 关键词条件不再生效，页面只显示链接指定的那一条时间线项

### Requirement: 时间线项菜单可以复制分享链接

时间线项菜单 SHALL 对所有读者提供「复制分享链接」，复制包含该条目 ID 条件的完整链接，并给出成功或失败的反馈。复制操作 MUST NOT 改变当前 URL、筛选条件或查询结果。打开该链接 MUST 显示仅包含该条目的时间线，读者 MUST 能清除该条件回到未筛选的列表。私密条目 SHALL 同样提供该入口。菜单 SHALL 按「打开链接」「复制分享链接」「只看当前类型」排序；缺少原始链接时省略「打开链接」。

#### Scenario: 复制并打开分享链接

- **WHEN** 读者在时间线项菜单点击「复制分享链接」，再把剪贴板中的链接发给他人打开
- **THEN** 打开者看到仅包含该条目的时间线，搜索框显示可删除的 ID 标签

#### Scenario: 复制时保留当前筛选

- **WHEN** 读者在关键词或来源筛选结果中复制某条条目的分享链接
- **THEN** 剪贴板包含该条目的 ID 链接，当前 URL、搜索框与结果保持原样

#### Scenario: 剪贴板不可用

- **WHEN** 浏览器拒绝写入剪贴板
- **THEN** 客户端提示复制失败，当前结果与 URL 保持不变

### Requirement: 时间线项菜单可以只看当前类型

时间线项菜单 SHALL 提供「只看当前类型」，把该条目的来源服务写入类型条件并立即刷新列表。效果 MUST 与手动输入相同条件一致，URL 与搜索框 MUST 同步更新。

#### Scenario: 只查看某来源的内容

- **WHEN** 读者对一篇博客文章点击「只看当前类型」
- **THEN** 列表只显示该博客来源的时间线项，搜索框中出现可删除的类型标签

### Requirement: 按 ID 查询沿用可见性规则

列表与总数接口 SHALL 支持按时间线项 ID 精确筛选，并在分页与计数前与既有可见性条件一并生效。未登录访客或访客预览查询私密条目的 ID MUST 得到空列表与零计数，MUST NOT 通过状态码或错误信息透露该条目是否存在。合法管理员会话 SHALL 能查看私密条目。格式非法的 ID 参数 MUST 返回 HTTP 400。

#### Scenario: 访客打开私密条目的分享链接

- **WHEN** 未登录访客打开一条私密时间线项的分享链接
- **THEN** 页面显示无结果状态，不显示该条目的任何内容

#### Scenario: 管理员打开私密条目的分享链接

- **WHEN** 已登录管理员打开同一条私密时间线项的分享链接
- **THEN** 页面正常显示该条目

#### Scenario: 传入非法的 ID 参数

- **WHEN** 请求携带格式非法的 ID 查询参数
- **THEN** 接口返回 HTTP 400

### Requirement: 离散操作立即写入 URL

删除标签、点击「只看当前类型」、打开含条件的链接与切换排序 SHALL 立即写入 URL。复制分享链接 MUST NOT 写入当前 URL。关键词输入的 URL 更新 SHALL 在短暂防抖后执行，避免每次按键都改写浏览历史。

键入的结构化条件 SHALL 在空白或 Enter 确认后提交，完整粘贴 SHALL 立即提交。输入法合成期间 MUST 保留草稿并暂停提交。菜单条件更新 MUST 合并当前关键词草稿，已过期的异步操作 MUST NOT 取消当前 URL 下的输入提交。同一关键词语义的 URL 回写 MUST 保留继续输入所需的空白。

#### Scenario: 切换排序

- **WHEN** 读者在排序菜单选择按更新时间排序
- **THEN** URL 立即包含 `orderBy=updated_at`，结果随即按更新时间排列
