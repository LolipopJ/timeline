# Design

## Context

`TimelineHome` 用 SWR 分页并按当前排序插入跨年标题。页面有桌面侧栏和移动端顶栏，滚动时从可见条目读取日期。来源和日期由各条目共用的 `TimelineItemLabel` 渲染，桌面上位于正文右侧。全局 CSS 已用变量映射 Tailwind 颜色，但 Markdown 样式、部分来源色和控件颜色固定为水墨深色界面设计。客户端采用 Next.js 静态导出。

## Goals / Non-Goals

**Goals**

- 让同一条纵轴承担年月定位和条目阅读顺序，并让窄屏优先留出正文宽度。
- 从页面根节点应用主题，使首屏、弹窗及长文阅读使用相同的颜色语义。

**Non-Goals**

- 跨年跳转、日期范围查询、账号级主题同步和站点级主题配置。

## Decisions

### 沿用现有查询，以已加载条目建立年月章节

在 `TimelineHome` 按服务端返回顺序遍历已合并的分页结果，用 `orderBy` 对应的时间字段计算本地年月，生成带标题的年份和月份章节。首条记录总是开启章节，后续仅在边界变化时开启新章节。保留既有加载入口，章节和当前阅读年月只从当前查询与视角的结果派生。

桌面采用「时间栏、装订线、正文栏」的对齐关系。移动端把装订线收进左侧页边距，将日期移到条目头部。年份以菱形标记章节，月份使用短横线刻度，条目日期使用等宽数字并保留完整的机器可读时间。来源、私密及新增或更新状态共用同一行的版式，长内容和媒体继续由现有来源组件渲染。

### 用当前阅读年月代替按条数估算的进度

桌面侧栏与移动端顶栏共用同一个当前年月。以顶部工具区下方的阅读起点为基准，月份取最近一个已经越过该位置的月份首条记录。阅读起点在首条记录之前时显示首月，列表为空时清空年月。可滚动页面到达底部时显示末月，让较短的最后一个月份也能被定位。滚动、视口大小和内容布局变化时更新工具区的当前年月，正文刻度统一使用静态样式。移除旧进度条和仅服务于它的条目索引。

工具区左上角沿用两行年月设计，上方以正文色显示中文大写年份，下方显示季节月份文案。月份沿用各自的季节色系，水墨深色使用较亮的色值，纸张浅色使用较深的色值。月份切换时，旧文案向下淡出，新文案从上方淡入，两者共用同一行空间。启用减少动态效果时直接切换。正文刻度继续使用数字年月。站点链接以图标显示在桌面侧栏左下角，与右下角悬浮按钮共用视口底部间距。在窄屏，站点链接收进右上角菜单，搜索框随顶栏的剩余空间伸缩。

### 在根节点切换两套颜色变量

水墨深色以略偏冷的墨黑为页面底色，用两级表面区分阅读内容与交互区域。青绿用于链接和键盘焦点，实底强调控件使用深墨文字。危险操作和警示各有独立颜色，并配合文字或图标说明含义。装订线使用低对比色，控件边界使用更清晰的独立色值。

| 角色 | 水墨深色 |
| --- | --- |
| 页面墨黑底 | `#0B0D0E` |
| 阅读面及弹窗 | `#14181A` |
| 输入框与悬停表面 | `#1E2527` |
| 正文 | `#E7ECEA` |
| 次级文字 | `#A8B6B2` |
| 装订线与章节分隔 | `#34413F` |
| 控件边界 | `#667A75` |
| 链接、焦点及强调实底 | `#73CDB9` |
| 强调实底上的文字 | `#102622` |
| 危险操作与错误提示 | `#F09B98` |
| 警示提示 | `#E9BC73` |

纸张浅色用暖纸底、略亮的阅读面和墨色正文，纸感来自页边留白、分栏和细装订线。两种主题的正文均保持干净的实底，来源色集中在小图标，来源名称使用可读的文字色。

| 角色 | 纸张浅色起点 |
| --- | --- |
| 页面纸底 | `#F5EFE2` |
| 阅读面及弹窗 | `#FFF9EF` |
| 正文 | `#2D2922` |
| 次级文字 | `#5F584C` |
| 装订线与章节分隔 | `#D8CDBA` |
| 控件边界 | `#817461` |
| 链接及焦点 | `#285E52` |

沿用 `globals.css` 的颜色变量和 Tailwind 映射，补齐装订线、控件边界和状态所需的颜色角色。盘点固定的水墨深色值，包括菜单、私密与错误提示、引用、代码块和 Steam 隐藏文字。复用已安装的 `github-markdown-css` 颜色变量和基础排版，使 Markdown 色彩跟随站内主题。根节点同时声明对应的 `color-scheme`，让浏览器原生表单控件与页面匹配。

技术博客标题在水墨深色下使用白色，在纸张浅色下使用墨色。悬停或键盘聚焦时，标题底色从左向右铺开，形成荧光笔效果。

### 在静态首屏读取浏览器偏好

使用一个本地存储键保存 `dark` 或 `paper`。静态页面头部用固定的同步脚本解析主题。有有效的保存值时优先恢复。首次访问或保存值无效时读取 `prefers-color-scheme`，将系统水墨深色映射为 `dark`，将系统浅色映射为 `paper`，并保存解析结果。浏览器无法报告系统配色时使用水墨深色。存储读写失败时仍应用本次解析出的主题。

脚本在首屏绘制前设置 `html` 的主题属性。客户端控件挂载后从根节点同步状态，切换时更新根节点并覆盖本地记录。将预期的 hydration 属性差异限制在根节点，主题入口放在现有工具区，并保持焦点和当前滚动位置。

## Risks / Trade-offs

- 同一月份横跨多个分页 → 合并后再分组，并用跨页且跨年的数据验证章节顺序。
- 高条目、图片加载和窄屏工具栏会影响定位 → 统一使用正文阅读起点和实际布局判断月份，验证快速滚动与改变视口后的显示。
- 浅色下固定的来源色、提示色或 Markdown 水墨深色变量会失去可读性 → 在两种主题下检查正文、链接、控件、焦点和状态，使用真实的混合内容与管理界面验收。
- 主题偏好在 hydration 后才读取会出现闪色 → 在构建后的静态产物中分别检查系统水墨深色、系统浅色和已保存主题的首屏颜色，以及控制台的 hydration 表现。

## Migration Plan

随客户端静态构建发布。回滚时恢复上一版客户端静态产物。
